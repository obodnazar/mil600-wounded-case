# BPMN AS IS і TO BE

AS IS — історичний комплект фази 4 нижче. TO BE — [окремий пакет для кроку II](../06-to-be.md), дострокова частина фази 9 за рішенням Назара; не фінальне приймання всього проєкту.

## AS IS — комплект фази 4

- [as-is.bpmn](as-is.bpmn) — канонічний BPMN 2.0 XML із DI; редагуйте його в BPMN-редакторі.
- [as-is.svg](as-is.svg) — векторний експорт XML через **bpmn-js 18.31.1**, для перегляду зі збільшенням.
- [Опис, джерела й межі](../03-as-is.md) — обов’язкова частина схеми; `*` позначає припущення / неперевірену нормативну деталь.
- [Рев’ю](../reviews/phase-4.md) та [рішення про порядок фаз](../decisions.md).

## Відкрити й експортувати

1. Завантажте `as-is.bpmn` і відкрийте через **Open diagram** у [bpmn.io](https://demo.bpmn.io/) або локальному редакторі на bpmn-js. Файл містить лише навчальні ролі та описи.
2. Для цілого маршруту використайте **Fit viewport**, для читання — збільшення. Широку схему зручно читати в SVG.
3. Після правок збережіть BPMN XML та повторно експортуйте **SVG** через меню редактора; перевірте обидва файли разом. SVG — похідний файл.

Імпорт / `saveSVG()` описані в [bpmn-js](https://bpmn.io/toolkit/bpmn-js/walkthrough/). Документація без дати публікації, перевірена 2026-11-13. Фактично перевірено локальний bpmn-js Modeler, а не ручне завантаження на публічний demo-сайт.

## Повторити структурну перевірку

Потрібен Node.js із підтримкою ESM та `require()` для ESM-залежності (використано **26.8.2**). Залежності встановлюються поза репозиторієм; це не вибір стеку прототипу.

```sh
qa_dir="$(mktemp -d)"
npm install --prefix "$qa_dir" --ignore-scripts --no-audit --no-fund --save-exact bpmn-moddle@10.3.1
node docs/bpmn/validate.mjs "$qa_dir/node_modules"
```

Запускайте з кореня репозиторію. Скрипт завершується ненульовим кодом за помилки й перевіряє:

- читання та round-trip через [bpmn-moddle](https://github.com/bpmn-io/bpmn-moddle) без попереджень;
- сім доріжок, належність вузлів, посилання, `incoming` / `outgoing`, DI;
- підписи й default-гілки, досяжність вузлів та шлях до завершення;
- межі підпроцесів, ортогональні стрілки без проходу крізь сторонні вузли;
- non-interrupting таймери довідки й контролю тривалого лікування.

Документація bpmn-moddle без дати публікації, перевірена 2026-11-13. Скрипт не є XSD-валідатором, юридичною перевіркою чи повним симулятором BPMN.

Окрема XSD-перевірка за наявності Python із `lxml`:

```sh
python3 - "$qa_dir/node_modules/bpmn-moddle/resources/bpmn/xsd/BPMN20.xsd" docs/bpmn/as-is.bpmn <<'PY'
import sys
from lxml import etree
schema = etree.XMLSchema(etree.parse(sys.argv[1]))
schema.assertValid(etree.parse(sys.argv[2]))
print("BPMN20 XSD: valid")
PY
```

## TO BE — комплект для кроку II

- [to-be.bpmn](to-be.bpmn) — канонічний BPMN 2.0 із DI; один концептуальний процес, огляд і сім площин деталей вкладених підпроцесів.
- [to-be.svg](to-be.svg) — огляд; деталі: [допомога](to-be-care.svg), [ініціація](to-be-intake.svg), [довідка](to-be-certificate.svg), [ВЛК](to-be-vlk.svg), [винагорода](to-be-reward.svg), [ОГД](to-be-ogd.svg), [події / звірка / супровід](to-be-control.svg).
- [Опис і AS IS → TO BE](../06-to-be.md), [рев’ю](../reviews/phase-9-to-be.md), [рішення / черга](../decisions.md).

SVG — експорт **тих самих DI-площин XML** через bpmn-js, не окрема перемальована схема. Відкрийте XML у сумісному BPMN-редакторі; для гарантованого читання деталей доступні всі SVG. Локально перевірено `Modeler.open('Diagram_vlk')` та відповідні ID: `Diagram_overview`, `Diagram_care`, `Diagram_intake`, `Diagram_certificate`, `Diagram_reward`, `Diagram_ogd`, `Diagram_control`. Перемикання всіх площин у конкретному сторонньому редакторі не перевірялося.

Одна pool — навчальна координація різних уповноважених учасників, не єдина організація. Модель `isExecutable=false`: таймери / умови описові, права реальних API не встановлені. Юридичний строк не визначається за невідомого якоря; дата внесення еПМК може задати лише попереднє нагадування «дату отримання підтвердити» за застосовності дій противника. Див. [ADR 0006](../architecture/adr/0006-primary-trigger-and-certificate-clock.md). Після завершення показаного проходу нове звернення потребує нового проходу координації з тим самим контролем; подієвий підпроцес не є вічним фоновим процесом чи автоматичним закриттям WoundCase.

### Відтворити TO BE

З кореня репозиторію; залежності лише в тимчасовому каталозі. Використано Python 3 зі стандартною бібліотекою, Node.js **26.8.2**, bpmn-moddle **10.3.1**, bpmn-js **18.31.1**, Playwright **1.62.1** і локальний Chrome. Це інструменти документації, не вибір стеку прототипу.

```sh
qa_dir="$(mktemp -d)"
npm install --prefix "$qa_dir" --ignore-scripts --no-audit --no-fund --save-exact bpmn-moddle@10.3.1 bpmn-js@18.31.1 playwright@1.62.1
python3 docs/bpmn/generate-to-be.py
node docs/bpmn/validate-to-be.mjs "$qa_dir/node_modules"
xmllint --noout --schema "$qa_dir/node_modules/bpmn-moddle/resources/bpmn/xsd/BPMN20.xsd" docs/bpmn/to-be.bpmn
node docs/bpmn/export-to-be.mjs "$qa_dir/node_modules" "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" "$qa_dir/images"
```

На іншій ОС передайте шлях до локального Chrome. `generate-to-be.py` відтворює XML; `export-to-be.mjs` читає його, перевіряє імпорт / round-trip, експортує вісім SVG і за третім аргументом створює PNG лише для локального QA. `xmllint` перевіряє BPMN20 XSD зі стандартним комплектом включених схем. Python `lxml` для цього запуску не потрібен. PNG не є окремим результатом здачі: користувач прямо попросив SVG.

Канонічні зміни вносьте в генератор і перегенеруйте XML / SVG разом. Якщо редагуєте XML у редакторі, перенесіть зміни в генератор до наступної генерації; інакше він їх перезапише. Збережені AS IS XML / SVG не змінюються.

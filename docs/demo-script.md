# Репетиція показу

**2026-11-13 · пропозиція для команди, не виміряний час виступу.** Канонічні назви кнопок, fixtures і всі винятки — [README прототипу](../prototype/README.md). D1 та [лінія відсікання](architecture/demo-plan.md) збережені. Не вводьте реальних даних; перемикач ролей навчальний.

## Підготовка

1. У `prototype/` виконати `npm ci --ignore-scripts && npm run dev`, відкрити `http://127.0.0.1:4317`. Інший мережевий host не підтримується.
2. Для нового прогону зупинити **власний** сервер, `npm run demo:reset`, знову `npm run dev`. Не скидати чужу сесію або невідому БД. Reset не потрібен для читання готових екранів.
3. Звірити банер вигаданих даних і ролі. Тримати [огляд TO BE](bpmn/to-be.svg), [пітч](pitch-one-pager.md) та [Q&A](pitch-notes.md) поруч. Скриншоти — резерв пояснення, не доказ живої роботи.

## Три блоки основного показу

| Блок | Дія | Що сказати / перевірити |
|---|---|---|
| Походження й довідка · D1.1–3 | Dev: `primary`, `admit`, `care-start`, `transfer`, `patient-receipt`; перегляд бійця. `certificate-prepared`; Командир кейсу 01: «Запит видачі довідки»; Dev: `certificate-issued`, `certificate-sent`, `certificate-received` | Основний сигнал з медичного джерела. Команда людини ще не є підтвердженням джерела. Начальник медслужби склав довідку про обставини травми (додаток 5 до Наказу №402), командир видає. Відправлено й отримано — різні стани |
| Два фінансові шляхи й ВЛК · D1.4–6 | Dev: `reward-packet`, `reward-approved`, `reward-execution_partial`, `reward-execution_confirmed`. Командир: «Направити на ВЛК»; Dev: `referral`, `vlk-received`, `vlk-decision`, `service-executed`. Далі `ogd-packet`, `ogd-returned`, `ogd-approved-after-returned`, `ogd-execution_partial`, `ogd-execution_confirmed`, `ogd-oct-packet`, `ogd-oct-approved` | Винагорода проходить до завершення ВЛК. Технічний checklist не вирішує клінічну достатність і не блокує направлення. ОГД окрема: повернення, рішення, виконання, інший період. Сума й право не обчислюються |
| Межі доступу й вимір · D1.7–8 | Аналітик: BO / невідоме; Dev «Мала група…», повернутися до аналітики. Супровід створює адміністративний резерв для 02, Dev `reserve-primary`; показати повтор події | Аналітика — окремий фіксований вигаданий зріз, без причинного висновку. Резерв не створює медичного факту чи нового доступу родині. Повтор не множить наслідків |

Між блоками робіть паузи на читання панелей. Звичайний сервер має 30 мутацій за хвилину й окремий gateway limit; повний прогін не вміщається в одну хвилину. При 429 зачекати вказаний інтервал і повторити ту саму дію. Не підвищуйте ліміт для презентації; тестовий сервер із підвищеним лімітом ізольований від звичайного запуску.

## Винятки на запит комітету

Після D1 або на чистому seed окремим прогоном: `care-unknown` — немає вигаданої дати; `gap` / `gap-recovered` — прогалина не зникає від іншого сигналу; виправлена версія довідки не успадковує отримання попередньої; `uncertain` — перевірена особа й ручне зіставлення випадку; адміністративний резерв без еПМК з `reserve-hospital` / `reserve-hospital-receipt`. Не змішуйте взаємовиключні сценарії на одному вже завершеному пакеті. Точний порядок — у README.

У службовій панелі немає місця лікування й клінічних refs; серверні 403 / 404 та негативні сценарії відтворюють [тести](../prototype/server/app.test.ts), [e2e](../prototype/e2e/panels.spec.ts). Нове представництво не демонструємо як готову функцію. П’ять днів лише за дій противника від визначеного отримання; внесення еПМК — орієнтир «дату отримання підтвердити». Чотири календарні місяці від належного початку не скидаються переведенням. Таймери не створюють санкції.

Якщо часу бракує: скоротити пояснення косметики / графіків / повторюваних fixtures, зберегти логіку D1 та чесно назвати непоказані винятки з посиланням на перевірки. Не видавати прискорений виступ за повне людське приймання AC. Завершити рішенням зі сторінки пітчу; реальний пілот потребує окремих погоджень.

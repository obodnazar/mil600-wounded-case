## Межі знання за системами

| Система | Встановлено / основа | Що запросити у власника до реального обміну |
|---|---|---|
| MedEvac / МІС ЗСУ | A01, N04: еПМК і медичне авторство | Охоплення, контракт, стабільний patient / incident ref, підписант, версії, канал і підтвердження одержання |
| Кабінет ВЛК у МІС ЗСУ | N01–N02: електронний документ і технічний резерв | Фактичний інтерфейс пакета, статус одержання, версія постанови, дозволені службові поля |
| Цивільна МІС / ЦБД ЕСОЗ | A06–A09, N11 / N17 / N20: різні законні маршрути | Конкретний документ / тип запису, правова підстава, права МІС / пацієнта, згода за потреби, охоплення. API ЕСОЗ не дорівнює API кожної МІС |
| СЕДО | N01, N17: адресний документообмін | Контракт довідки / доставки, адресати, джерельний підпис і квитанція, паперовий резерв |
| «Імпульс» / ДРВ | A02–A04: різні облікові сутності | Дозволений маршрут ідентифікації, підтвердження служби / призначення та зміна частини. ДРВ не плутати з реєстром ветеранів чи «Оберегом» |
| Система грошового забезпечення / орган ОГД | N06, N07, N21: різні процеси | Назва системи й API **не підтверджені**; джерело підстави, рішення / нарахування / фактичного виконання, період і причини |
| Армія+ | A04, N19: користувацький сервіс / портал | Контракт довіреної сесії, ідентичності, ролей і вбудовування фічі; схему SSO не вигадуємо |
| ІКС «Супровід» | A05: анонс розробки | Поточна готовність, власник і межа нашого модуля; не стверджуємо, що система досі не запущена |

Запити підготовлено як питання, **не надіслано**. Немає доступів, реальних персональних / медичних записів, внутрішніх регламентів і production-погоджень. Baseline [TBD].

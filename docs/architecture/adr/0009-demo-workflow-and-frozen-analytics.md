# ADR 0009 — виконання синтетичного маршруту й фіксована аналітика

- Дата: **2026-11-13**. Статус: **реалізовано, на затвердженні разом із фазою 8б**.
- Підстава: прийняті F01–F10 / AC01–AC10, ADR 0001–0008; явний дозвіл Назара на повну реалізацію 8б, строгі схеми, mock-джерела, календар, фінансові переходи та рольові команди. Стек ADR 0008 не змінюється.

## Рішення

Один Node HTTP-процес / SQLite з міграціями виконує події шести **вигаданих** джерел. МІС ЗСУ — головна еПМК; СЕДО підтверджує видачу / відправлення / направлення, ВЛК — квитанцію / пакет / постанову, фінансове джерело — вид / період / мотив / рішення / виконання; службове джерело — отримання бійцем та адміністративне виконання; цивільне джерело — лише погоджений mock-канал. Це власний контракт, не специфікація реальних API. Нові поля додаються до строгих схем, клінічні body / URL / довільні документи не приймаються.

Дія людини записує `demo_command` і задачу очікування. Вона не підміняє джерельне підтвердження. Права повторно перевіряються перед поверненням збереженого результату команди. Повтор із тим самим ключем не дублює ефект; той самий ключ з іншим наміром — конфлікт. Джерельна подія не створює AccessGrant. Адміністративний резерв має відому особу / випадок, чекає джерело; ручна звірка допускається тільки для відомої особи та невизначеного випадку у своїй області.

Opaque-версії не сортуються. Потрібен явний попередник для зміни потоку / документа / пакета / фінансового рішення; суперечність відкладається на розбір. Невідомий фінансовий сигнал не стирає підтверджене рішення чи часткове виконання. Вид і період ізольовані. Копія з готової галереї залишається копією після технічної перевірки. Нова версія документа не успадковує квитанцію адресата.

Календар обчислюється датами `Europe/Kyiv`: дні за ст.260 й календарні місяці за N05. Невідомий початок / застосовність не дає строку. Дата внесення еПМК дає тільки орієнтир «дату отримання підтвердити». Після минулого підтвердженого строку worker створює одну задачу людині на ревізію розрахунку; не змінює виплат чи облікового статусу. Нормативні джерела й редакції — [N16](../../../regulation/internal-service-548.md), [N05](../../../regulation/social-protection-2011.md), [N07](../../../regulation/lump-sum-975.md).

Для аналітика при ініціалізації зберігаються **незмінні** результати розрахунку окремої підготовленої mock-когорти (30 вигаданих спостережень) і приклад малої групи. Вони обчислюються сервером у `metrics.ts`, а не прописані як готові відповіді у UI. Це **інша підготовлена когорта, ніж живі кейси D1**; довільних фільтрів / часового перевидання / індивідуальних рядків немає. Поріг 5 застосовано до клітинок, доповнювальних груп і покриття; малий зріз не публікує точного розміру. Нульовий / невідомий знаменник дає «Недостатньо даних». BO-4 — окремий зовнішній контекст з першоджерелом, не результат демо. Baseline [TBD].

## Альтернативи й наслідки

- Живі агрегати після кожної події D1: відхилено через малу когорту й віднімання послідовних зрізів. Публікаційний механізм для реальних даних — окремий production-обсяг.
- Довільний JSON / завантаження файлів: відхилено; fixed fixtures і галерея виконують навчальний сценарій без приймання реальних даних.
- Нові майстри й складні графіки: за лінією відсікання. Вибір fixture та одна форма дій зберігають усі AC.

Залишаються локальна демо-роль замість SSO, loopback HTTP, власник SQLite може змінити файл / тригери, підпис джерел демонстраційний. Повного ASVS L2 / захисного допуску / production / реального електронного документообігу немає. [Приймання й обмеження](../../prototype-8b.md).

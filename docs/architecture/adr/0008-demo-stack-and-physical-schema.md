# ADR 0008 — стек локального демо й фізична схема 8а

- Дата: **2026-11-13**. Статус: **запропоновано на затвердження 8а**, не production-рішення.
- Підстава: Назар затвердив фазу 7, варіант А; контрольна точка 8а прямо передбачає вибір стеку, міграцію / seed і перші екрани чотирьох панелей до повної розробки 8б.

## Варіант А — рекомендація для цього демо

**React 19.3.1 + Vite 8.3.8, TypeScript strict; один Node.js 26.8.2 HTTP-сервер і SQLite через вбудований `node:sqlite`.** SQL-міграція з параметризованими запитами, без ORM. UI збирається в локальні assets, API й сторінка мають один origin. `npm run dev` збирає UI / сервер, застосовує міграцію та seed і слухає лише `127.0.0.1`. Немає окремого dev proxy, контейнера, брокера чи другого сервісу. Worker працює в тому самому процесі, обробляє лише локальний outbox.

Це реалізація прийнятого модульного сервера й реляційних транзакцій ADR 0002–0005. Початкове завдання **рекомендує**, але не зобов’язує Next.js / PostgreSQL / Prisma. SQLite обрано для одного локального синтетичного показу: запуск без Docker / адміністратора БД, відтворювана перевірка rollback і повторів, невеликий seed. Docker у перевіреному середовищі не знайдено. Домен і права не переносяться в клієнт; React не отримує DB / source keys. Це не твердження, що такий стек підходить установам.

## Фізична модель

[001-initial.sql](../../../prototype/db/migrations/001-initial.sql) реалізує **22 логічні сутності** з [моделі фази 6](../data-model.md). Шість технічних таблиць: `schema_migration`, `seed_snapshot`, `demo_unit`, `demo_provider`, `demo_session`, `transport_nonce`. Довідники груп і закладів містять лише навчальні назви. Міграція версійована й має checksum; зміна вже застосованого SQL відхиляється. До першого PR 8а схема створюється з нуля; наступні зміни — новою міграцією.

- FK / STRICT / UNIQUE: підтверджений incident у namespace, дві осі inbox-дедуплікації, локальна версія документа, пакет / ревізія / instance, адресат отримання, вид / період фінансового треку. Композитні FK не дозволяють доказ документа з іншого кейсу чи виправлення чужого документа.
- Перетин перевірених identity token / службових призначень не застосовується мовчки: insert **і update** відхиляються, далі потрібен розбір. Невідомі incident не об’єднуються за особою; подія не створює AccessGrant.
- Склад ревізії пакета та журнали CaseEvent / AuditEntry захищені від звичайного update / delete тригерами. SQLite-власник файлу може змінити схему: це **не незмінний зовнішній аудит** й не окремі DB-ролі.
- `due_date` неможливий без confirmed anchor / дати й застосовності. Estimated має лише окремий орієнтир; виконана / частково виконана виплата потребує execution ref. Дати seed — **готові вигадані fixtures**, не реалізований юридичний календар.
- WAL + synchronous FULL, одна `BEGIN IMMEDIATE` транзакція: inbox, мінімальна зміна кейсу / задачі, CaseEvent, audit, outbox. Помилка аудиту відкочує всі ці ефекти. Durable nonce діє 601 с, inbox-дедуплікація не очищається; до 1000 подій у цьому демо, далі відмова замість втрати ledger. Невизначені ревізії / mapping — ReviewItem, без сортування opaque version.

Первинний handler еПМК реалізований мінімально; інші валідні типи можуть бути стійко записані як `pending_8b` / `pending_review`, **business_applied=false**. 202 означає запис у БД, а не завершення всіх доменних дій чи доставки назовні. Старий HTTP harness фази 7 лишається `validated_only`; застосунок використовує ті самі `Ingress.authenticate` / schema / source policy, але persistent ledger. Dev-кнопка викликає спільний gateway з реальним для демо HMAC, без прямої зміни стану БД; це внутрішній виклик тієї ж функції, не мережевий webhook установи.

## Сесії й секрети

Демо-вибір ролі мапується на **серверний** фіксований roster. Випадковий opaque session token зберігається як hash; HttpOnly / SameSite=Strict, TTL 15 хв, ротація при зміні ролі. Роль / purpose / grants / UnitAssignment перевіряються з БД на кожний запит. Mutation потребує точного Origin і CSRF, Host / loopback перевіряються; proxy headers не дають довіри. Cookie без Secure лише тому, що дозволено виключно локальний HTTP. Справжньої авторизації немає: кожний локальний користувач може вибрати будь-яку **навчальну** роль.

На першому запуску без жодного source key CLI генерує окремі випадкові ключі у приватний ігнорований `.runtime/local.env`, далі завантажує їх у env-helper фази 7. Частково заданий набір env відхиляється. Папка 0700, файл / БД 0600, umask 077; ключі не друкуються, не комітяться й не включаються у browser bundle. Це локальний bootstrap, не secret manager. Production / не-loopback startup відхиляються. Невідома непорожня БД відхиляється до зміни її схеми.

## Альтернативи й наслідки

**Б) Next.js + PostgreSQL + Prisma / Drizzle + Docker.** Ближче до початкової рекомендації; більше готових framework / DB механізмів і багатокористувацького розвитку. Потребує окремого PostgreSQL / контейнерного оточення й перенесення SQL / тестів до 8б. Обрати, якщо команда вже має цей стек і хоче підтримувати його після курсу; поточна реалізація А тоді не вважається затвердженою production-основою.

**В) Статичний UI з JSON** не задовольняє серверні права / durable події й відхилений без зміни концепції. Обсяг F01–F10 / AC01–AC10, чотири панелі, D1 та лінія відсікання не скорочені. Рішення 8а затверджує стек і перші екрани; повне функціональне приймання — 8б.

SQLite має одного writer, синхронні запити блокують процес, немає відокремлених ролей / RLS, шифрування БД чи production backup / restore. Модуль `node:sqlite` у перевіреній версії має статус release candidate; Node pin захищає від неперевірених змін API. HTTPS / SSO / secret manager / зовнішній аудит / реальні інтеграції / експлуатаційні допуски залишаються окремою роботою. Це не повний ASVS L2.

## Джерела вибору

Версії перевірені `npm view` / lockfile **2026-11-13**; дати публікації цих конкретних npm-релізів тут не встановлювалися. Публічна технічна документація без окремої дати публікації, відкрита 2026-11-13:

- [React Quick Start](https://react.dev/learn), [Vite Guide](https://vite.dev/guide/) — UI / збірка.
- [Node 26.8.2 SQLite](https://nodejs.org/download/release/v26.8.2/docs/api/sqlite.html) — перевірена API-версія / prepared statements / статус модуля.
- [SQLite foreign keys](https://www.sqlite.org/foreignkeys.html), [transactions](https://www.sqlite.org/lang_transaction.html) — FK і обмеження writer / транзакцій.
- [Публічні скриншоти App Store](https://apps.apple.com/ua/app/%D0%B0%D1%80%D0%BC%D1%96%D1%8F/id6499126615) — візуальна звірка браузером 2026-11-13; дата публікації скриншотів не вказана. Відтворені загальна палітра / округлі картки / контраст, без копіювання логотипів, емблем, тризуба, фото чи шрифтових файлів. Системний Arial / Helvetica, без зовнішніх font requests.

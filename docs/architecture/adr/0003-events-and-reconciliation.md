# ADR 0003 — події та погоджена звірка

- Дата: 2026-11-13. Статус: **прийнято, варіант А**. Назар затвердив фазу 6, логічну модель, доступи та ADR 0002–0005 2026-11-13; [рішення](../../decisions.md). Це не погодження установ / production-допуск.
- Основа: F01–F06 / F09, [контракт](../event-contract.md), [межі реальних джерел](../sources.md).

## Рішення

Домен приймає нормалізовані події. Кожен реальний адаптер використовує підтверджений власником спосіб — повідомлення або погоджене вибіркове читання змін. Не припускаємо webhook чи FHIR Subscription у МІС / ЕСОЗ. Немає такого доступу — задача уточнення й чинний документний маршрут.

У демо — transactional inbox / outbox і воркер у межах однієї реляційної БД, без окремого брокера. Повторна доставка очікувана; атомарне застосування, source version, ключі ідемпотентності й ручний розбір забезпечують відсутність дублювання. Журнал подій та змінювані поточні стани зберігаємо разом; це не повна event-sourcing-платформа.

## Альтернативи

- Лише синхронний API-запит із браузера: простіше макетувати, але обрив мережі змішує приймання й виконання, розкриває джерельні доступи; не обираємо.
- Лише push без звірки: ризик пропущених подій; дозволений reconciliation обов’язковий, де джерело його підтримує.
- Постійне опитування всіх систем: непідтверджені права, навантаження й зайві дані; не обираємо. Вибіркову звірку погоджує власник.
- Окремий message broker: можливе майбутнє розширення, якщо потрібні обсяг / ізоляція; до демо не є залежністю.

Зовнішні гарантії exactly-once не заявляємо. Подія автентичного джерела не звільняє від перевірки особи, випадку й доступу. Підпис конверта не є КЕП медичного документа.

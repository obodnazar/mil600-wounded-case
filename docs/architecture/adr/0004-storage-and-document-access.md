# ADR 0004 — метадані й документний доступ

- Дата: 2026-11-13. Статус: **прийнято, варіант А**. Назар затвердив фазу 6, логічну модель, доступи та ADR 0002–0005 2026-11-13; [рішення](../../decisions.md). Це не погодження установ / production-допуск.
- Основа: BR-2 / BR-7, [ADR А](0001-legal-boundaries.md), [модель](../data-model.md), N09 / N11–N15.

## Рішення

Основна БД зберігає мінімальні адміністративні метадані, версії правил, джерельні opaque refs і дозволені стани. Клінічні документи / діагнози лишаються в джерелах; raw response ЕСОЗ не зберігається в inbox, логах, аудиті чи outbox. Подія проходить мінімізацію в погодженому адаптері, а строгий вхід оркестратора відхиляє зайві поля.

DocumentRef — пара source namespace / record ref / version, а не довільний URL для server-side fetch. Контрольований доступ перевіряє особу, кейс, поле, scope і права джерела перед кожним читанням; не повертає зовнішні bearer-токени чи необмежені лінки командиру. Одержання документа ВЛК має окрему квитанцію потрібної версії / адресата.

Запасне фото в реальному сервісі вимагало б окремого захищеного сховища, перевірки вмісту / джерела, прав та політики видалення; воно не стає оригіналом. У демо — лише підготовлені вигадані зразки з тими самими перевірками ролі; приймання реальних файлів не реалізувати.

## Альтернативи й наслідки

- Копіювати весь клінічний архів у кейс: простіше автономне читання, але зайві дані, права й ризик розкриття; не обрано.
- Дати прямі URL усім учасникам: простіше UI, але витік / обхід ролей / SSRF; не обрано.
- Повністю заборонити резерв: не працює для непідключеного каналу; лишаємо адміністративний маршрут і контрольований демо-зразок.

Метадані теж чутливі. Реальні retention, backups, шифрування, ключі, категоризація й авторизація з безпеки [TBD] до production; строк зберігання ПМК не переноситься на нашу БД. Видалення технічних повідомлень узгоджується зі збереженням ключів дедуплікації й нормативно потрібного аудиту.

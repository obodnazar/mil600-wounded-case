# ADR 0007 — перевірюване ядро безпеки до вибору стеку

- Дата: **2026-11-13**. Статус: **прийнято Назаром 2026-11-13, варіант А**.
- Підстава: завдання фази 7 прямо вимагає реалізувати захист і тести / CI; фаза 8а окремо зберігає вибір фреймворку / БД та показ усіх чотирьох панелей.

## Рішення

Реалізувати переносиме TypeScript strict ядро безпеки та локальний HTTP-тестовий adapter на вбудованому Node HTTP. JSON Schema / AJV перевіряють власний конверт; Node crypto / fs забезпечують транспорт і тестовий приватний аудит. Ці інструменти виконують прямо доручену фазу 7, **не обирають UI-фреймворк, СУБД, ORM, фізичні міграції чи production-хостинг**.

Adapter існує тільки для синтетичних негативних перевірок, тест слухає loopback на випадковому порту. Немає автоматичного CLI / публічного deployment, SSO, app-сесій або доменного застосування подій. Ledger / source scopes тестові, не persistent inbox. Відповідь `validated_only`, `business_applied=false`; приймання після durable commit з ADR 0003 лишається вимогою 8а.

У 8а під’єднати ці самі контролі до обраного web framework / storage ports, не писати слабкий паралельний mock-шлях. Повторити HTTP й наступні e2e перевірки на фактичних endpoint / панелях; source event не змінює AccessGrant. Довідники / доменні сутності / календар / BO залишаються за прийнятими ADR 0001–0006.

## Альтернативи

Лише Markdown / тести-муляжі без HTTP не довели б обов’язкові перевірки фази 7. Повний застосунок / БД до 8а обійшли б точку рішення користувача. Обрано вузьку реалізацію P0, із чесними незакритими ризиками й новим прийманням після інтеграції; повного ASVS L2 / production-допуску не заявлено.

# ADR 0001 — правові межі ролей, джерел і строків

- Дата: **2026-11-13**.
- Статус: **прийнято, варіант А**. Назар затвердив фазу 3 і цей варіант 2026-11-13; [журнал рішення](../../decisions.md). Не production-допуск і не рішення про MVP.
- Основа: [рішення фази 2](../../decisions.md), [матриця L01–L21](../../../regulation/legality-matrix.md), [конспекти N01–N21](../../../regulation/README.md).

## Контекст

Ядро команди — фіча Армія+, ведення маршруту, подія еПМК і необхідна службова видимість лікування — зберігається. Дослідження фази 2 затверджене як гіпотеза; C6 виключений, C2 лишається підгіпотезою. Початкова концепція містила неперевірені твердження про автора ПМК, усі епікризи з ЕСОЗ, універсальні 120 діб та достатність метаданих для захисту.

## Прийняте рішення — варіант А

1. **Командир / супровід:** ініціює адміністративний кейс за зверненням / належною службовою інформацією, контролює задачі частини; командир видає довідку, яку складає начальник медслужби. Внесення №001/о лишається медпрацівникам. Адміністративна ініціація не підміняє документ і не доводить медичний факт (L01–L04).
2. **Видимість:** адресні службові дані про лікування в межах своїх повноважень; діагнози й клінічні записи не потрапляють у командирський інтерфейс. Конкретні поля / посадові доступи погоджуються володільцем; для представника потрібні перевірені повноваження (L06–L07, L17).
3. **Джерела:** еПМК у МІС ЗСУ — можливий автентичний тригер після погодження. Цивільні документи можуть надходити в чинних дозволених каналах, зокрема №901; широкий беззгодний експорт ЕСОЗ не вважається дозволеним законом №4497-IX. «Трембіта» / API не створюють правової підстави (L09–L12).
4. **Строки / виплати:** окремі календарні правила й вихідні події, жодного універсального «120 діб від поранення». Винагорода та ОГД — різні процеси; система підказує та ескалує, не змінює статус / право самостійно (L05, L15–L16).
5. **Підпис і захист:** фото / OCR не є оригіналом, інтеграції й підписи прототипу — симуляції. До реальних даних власник погоджує регламент, обмін, категорії й застосовний захисний допуск; «тільки метадані» не звільняє від цих вимог (L13, L19–L20).

## Альтернативи та наслідки

**А — прийнято:** реалізовувати навчальний концепт у наведених межах, чинні документні канали відображати як цільові погоджувані інтеграції, розширення позначити окремо. Це дозволяє показати цінність маршруту без неправдивої обіцянки готового доступу.

**Б — не прийнято, окремий можливий обсяг:** закласти широкий новий обмін без згоди, усунення всіх обов’язкових паперових примірників або нову самостійну публічну послугу. Спочатку потрібні зміни належного рівня НПА / класифікація послуги й рішення власників (L10, L12, L18); це окремий обсяг, а не передумова будь-якого електронного пакета.

Рішення не додає функцій медичної оцінки C6, не обирає стек і не визначає обсяг MVP. Фазу 4 не запускаємо повторно: [AS IS](../../03-as-is.md) отримує примітку про звірені норми, XML / SVG лишаються затвердженою навчальною моделлю з її припущеннями. Потребу структурної ревізії команда вирішує окремо.

## Підстава прийняття

Повідомлення Назара від 2026-11-13: «Затверджую фазу 3. Рішення: варіант А з ADR 0001 (адміністративна ініціація командиром без створення медичного факту; чинні дозволені канали й мінімальна службова видимість; розширення окремим обсягом)». Окремо дозволено злиття PR #4. Обсяг MVP у [фазі 5](../../05-product-concept.md) є новою пропозицією й цим ADR не затверджений.

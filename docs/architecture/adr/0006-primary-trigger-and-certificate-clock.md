# ADR 0006 — основний тригер й орієнтир строку документа

- Дата: **2026-11-13**. Статус: **прийнято за явним рішенням Назара** при затвердженні TO BE з двома правками. Уточнює ADR 0001, F01 / AC01 і F04 / AC04, не створює нового права доступу чи медичного факту.
- Назва: **довідка про обставини травми (додаток 5 до Наказу №402)**. У поточних матеріалах не використовуємо скорочення «Ф5» / «Форма 5». Начальник медслужби складає документ, командир видає його за своїми повноваженнями.

## Рішення

1. **Основний тригер кейсу — погоджена автентична еПМК з МІС ЗСУ.** Адміністративний запит командира / супроводу — лише запасний шлях, коли еПМК чи її подія недоступна. Не встановлюємо вигаданий час очікування події. Перевіряються особа, випадок і доступ; повтор або пізня подія долучаються до перевіреного кейсу. Командир не заповнює еПМК замість медпрацівника.
2. **Правило ст.260 №548-XIV — лише для захворювання / травми, спричинених діями противника.** П’ять днів від отримання військовослужбовцем первинного облікового медичного документа (зокрема еПМК), а за відсутності — довідки про перебування в закладі. Стаття передбачає складання та направлення у той самий строк. Дата створення еПМК, її отримання військовослужбовцем, надходження в наш inbox та одержання ВЛК — різні факти. [N16](../../../regulation/internal-service-548.md), [N01](../../../regulation/vlk-402.md), [N21](../../../regulation/pay-procedure-260.md).
3. **Орієнтир не підміняє юридичний строк.** За підтвердженої застосовності, коли отримання військовослужбовцем ще невідоме, дату внесення еПМК можна використати для попереднього нагадування: «Орієнтир за датою внесення еПМК; дату отримання підтвердити». `anchor_status=estimated`, `provisional_follow_up_date` — окрема дата, `due_date=null`. Це не доказ прострочки, не знаменник для обліку порушень і не причина повторно видати вже оформлений документ.
4. Після підтвердження дати отримання: `anchor_status=confirmed`, `anchor_date` з належного джерела, `due_date` за версією календарного правила; попередній орієнтир замінюється з аудитом. Якщо невідома застосовність або немає навіть дати внесення — уточнення без вигаданої дати. Отримання документа адресатом фіксується окремим Delivery.
5. **Без санкцій** для підтвердженого й попереднього нагадування: не створюємо / скасовуємо СЗЧ, не зупиняємо виплати, не відмовляємо в направленні чи праві. Людина перевіряє застосовність і стан, система координує.

## Наслідки й альтернативи

Обрано розділення `confirmed / estimated / unknown` замість автоматичного запуску юридичного строку від внесення еПМК чи поранення. Це виконує уточнення користувача й не змінює норму. Для демонстрації попереднє нагадування можна показати на дату внесення + п’ять календарних днів, із явним попереднім статусом; точний юридичний розрахунок / календар перевіряється окремо, граничні дати не вгадуються. Жоден event_type сам по собі не доводить застосовність правила.

# Ролі, поля й дії

**2026-11-13 · пропозиція політики, не реалізований захист.** Для реального сервісу поля / мету / посади погоджує володілець. Основа — [ADR А](adr/0001-legal-boundaries.md), N09 / N11 / N16–N18 і F10 / AC10. Відсутність клінічного тексту в БД не замінює авторизацію документних посилань.

## Контекст доступу

Сервер бере `actor_id`, перевірену роль, призначення, purpose і строк прав із довіреної сесії / призначення; **ніколи** з query/body `role`, `unit_id` чи видимого Army ID. Демо-перемикач лише обирає серверну seed-сесію; жодного відтворення production SSO. Кожний запит і повтор команди перевіряє чинний грант / відсутність відкликання та область кейсу. Default deny; кеш відповіді не повертає відкликані дані.

Командир має scope своєї частини лише за чинними повноваженнями; супровід — лише призначені кейси / область. Історичне перебування бійця в частині не дає необмеженого доступу після переведення. Межу передачі супроводу й продовження доступу за незакритими задачами погоджує власник; до того без гранта — відмова. Подія лікування не змінює призначення чи службовий статус.

## Джерельні service identities

Інтеграційний клієнт автентифікується окремо від людини й має allowlist типів, namespace, право на відповідні records / recipients. `demo-mis` не видає фінансову подію; `demo-sedo` не створює медичний факт; `demo-finance` не змінює особу / призначення. Dev-сесія викликає серверний адаптер, не отримує HMAC-ключ. За відсутності dev-режиму demo endpoint недоступний. Production-активація симулятора заборонена конфігурацією й перевіркою середовища.

Сервер повертає окремі DTO: командирський DTO взагалі не містить діагнозів, клінічних refs, повного response ЕСОЗ чи довільного мотивувального тексту. Мотив виплати — дозволений код / узгоджене пояснення без клінічних подробиць. Доступ до оригіналу / резервної копії перевіряється **окремо**; зберігання лінка не відкриває його для всіх.

## Агрегати й OPSEC

Пропонований навчальний параметр `min_group_size = 5` — **лише демо-конфігурація, не норма закону й не доказ анонімності**; значення й режим погоджуються у фазі 7. До погодження деталізація за частинами / закладами вимкнена. Мінімальна панель має фіксовану синтетичну когорту без довільних фільтрів, drill-down, географії та експорту рядків.

Окрім приховання малої групи потрібне комплементарне пригнічення: не можна повернути загальний підсумок і всі інші групи, з яких вона відновлюється відніманням. Версійовані фіксовані зрізи / обмеження запитів мають врахувати повтори й часові різниці; лічильник suppression не розкриває прихований точний розмір. Відсутній дозвіл / параметр — закрита деталізація, а не fallback до всіх даних. Реальна аналітика потребує окремої OPSEC-оцінки; мінімальний розмір групи її не замінює.

## Негативне приймання для фаз 7–8

- Командир: `GET /api/cases/:id/clinical-document` → **403**, навіть для своєї частини; raw clinical fields / refs відсутні і в звичайному DTO.
- Чужий кейс / нечинний scope → нерозкривальна відмова за погодженою HTTP-політикою; підміна unit / role у body не надає доступу. Негативний тест має перевіряти й API, не лише приховану кнопку.
- Супровід не може виконати команду видачі / направлення від імені командира; dev-джерело не проходить звичайною user-сесією. Звернення родича не створює session / AccessGrant.
- Відкликання / зміна частини відразу впливають на читання й повтор команди, включно з кешем. Потрібна перевірка контексту та авторизації об’єкта / поля.
- Аналітик не має endpoint списку людей; малі / комплементарні групи приховані на сервері. Невідомі знаменники не перетворюються на нуль.
- Доступ / відмова / зміна залишають аудит без медичного тексту; журнал не пише body або секрети. Стан не фіналізується, коли обов’язкова транзакція аудиту не відбулася.

Це план перевірок, **жоден тест доступу ще не виконаний на застосунку**. STRIDE / LINDDUN, конкретні транспортні механізми, заголовки, ліміти й допуск — окрема фаза 7.

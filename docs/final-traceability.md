# Фінальне трасування

**2026-11-14 (обсяг затверджено 2026-11-13).** Початок ланцюга — затверджена гіпотеза та болі 1–4, C2 лишається підгіпотезою, C6 поза продуктом. Нижче всі F01–F10 / AC01–AC10 і S1–S9; BRD задає бізнес-вимоги, BPMN — концептуальні кроки, тести — докази конкретного демо. Кількість вузлів не означає економії часу.

Машиночитане джерело: [final-traceability.json](final-traceability.json); структурна перевірка ID / файлів / повноти — [verify-final.py](../scripts/verify-final.py). Скрипт не перевіряє, що тест справді стосується вимоги: це звірено читанням тестів під час аудиту 2026-11-14.

**Стан доказів.** 2026-11-14 прототип переписано в межах незалежного аудиту, тому докази перев’язано на тести нової структури. Колонка «Доказ і межа» вказує, які тести перевіряють вимогу, а не те, що вони пройшли: запуск і результати — у [README прототипу](../prototype/README.md). Переписану версію команда ще не затверджувала. Тека `prototype/e2e/` ще доповнюється, тому названа цілком, без окремих сценаріїв.

Нормативні ID з датами актів / редакцій / перевірок — [реєстр](../regulation/README.md); ADR — [архітектура](architecture/README.md). Базове зіставлення болів / JTBD / AS IS / BR / F / AC / BO — [T01–T10 концепції](05-product-concept.md#9-матриця-трасування); сценарії, вузли AS IS і норми цієї матриці 2026-11-14 узгоджено з T01–T10 і таблицею сценаріїв концепції. Вузли TO BE тут — вибірка ключових; повний перелік за F і зміни прибрати / спростити / стандартизувати / автоматизувати — [порівняльна таблиця](06-to-be.md#as-is--to-be-прибрати--спростити--стандартизувати--автоматизувати).

BO-4 є зовнішнім контекстом. BO для F09 означають можливість перевірити інструментування, не причинний ефект; F10 накладає захисні умови на всі метрики. Для F08 AS IS ID позначають точки майбутнього вимірювання, не вигаданий аналітичний крок вихідного процесу.

**Часткове покриття (аудит 2026-11-14).** «9/9» у скрипті означає наявність ID у матриці, не повне виконання вимоги. BR-2 — лише симуляція каналу (реальні адаптери — беклог B02); BR-9 — лише через службу супроводу (представник — B03); BR-4 і BR-6 — у службовій проєкції через задачі, розбори, строк довідки й доступні дії, без закладу, документів і виплат ([питання команді](decisions.md#питання-аудиту-2026-11-14-що-чекають-рішення-команди)); BR-1 — панелі мають лише боєць, командир / супровід і аналітик. Основа F04 — норми N05 / N16 і непідтверджені C2 / A-3; для Б4 немає новішого прямого голосу пораненого, Б3 (обліковий статус) не має власної функції чи даних — AC07 у цій частині виконано відсутністю автоматичних висновків. Пояснення строку ОГД за п.23 Порядку №975 (AC06) — текст інтерфейсу, окремого автотесту не має.

ВЛК / медик / фінансовий орган у джерелах не є додатковими людськими панелями продукту. Беклог B01–B06, реальні інтеграції, офіційні підписи, клінічна оцінка й самостійний представницький доступ не позначені реалізованими. [Ризики / умови реальних даних](final-risk-disposition.md).

Це не статистика атак і не повний пентест. Позначення R01–R22 ведуть до [реєстру](risk-register.md), K01–K10 — до [контролів](controls.md).

## Активи, противники й межі

Активи: право на лікування / виплату й достовірний маршрут; ідентичність / випадок / чинний scope; навіть мінімальні дати лікування й refs; джерельні версії / квитанції; ключі / сесії; захищений аудит; агрегати; код / залежності. Реальна комбінація частини, кількості поранених і закладу може розкривати оперативну інформацію — це наш сценарій загрози, не доказ конкретного витоку.

Розглядаємо зовнішнього нападника, викрадений обліковий запис / ключ адаптера, надмірно допущеного працівника, помилку оператора / інтеграції, скомпрометовану залежність і шахрайську «службу допомоги». Користувач не контролює довірений контекст ролі; будь-який браузер, URL, заголовок, подія й ref недовірені до перевірки. Адміністратор довідників не стає медиком / аудитором.

Межі: **TB1** браузер → API; **TB2** джерело / dev-адаптер → шлюз; **TB3** API / воркер → сховище; **TB4** документний broker → джерело / демо-зразок; **TB5** індивідуальні метадані → агрегат; **TB6** сервіс → аудит / моніторинг; **TB7** Git / CI → залежності / артефакти. Зовнішні системи й TLS / SSO установ не підконтрольні студентському проєкту.

## STRIDE по кожному контейнеру / компоненту C4

S — підміна ідентичності; T — зміна даних; R — заперечення дії; I — розкриття; D — відмова в обслуговуванні; E — підвищення повноважень. Запис у клітинці — конкретна загроза, не позначка «усе захищено».

| Компонент | S | T | R | I | D | E | Контролі / залишок |
|---|---|---|---|---|---|---|---|
| Вебклієнт: чотири панелі | Підроблена сесія | Зміна role / unit у запиті | «Не відкривав кейс» | localStorage / скриншот / кеш | Часті запити | Прихована кнопка замість ACL | K01 / K05; UI / CSRF / сесія 8а, R01 / R10 |
| Dev-симулятор | Dev як production-джерело | Прямий запис у БД | Немає автора симуляції | Ключ у JS bundle | Потік fixtures | Увімкнення demo у production | K02 / K08; справжня dev-панель 8а, R02 |
| Зовнішні джерела | Викрадений ключ установи | Неправдивий авторський факт | Відсутня квитанція | Надмірна відповідь ЕСОЗ | Джерело недоступне | Невідомий API трактують як дозвіл | K02 / K03, погодження власника; R04 / R12 |
| Адаптер / нормалізація | Підміна source namespace | Зайві клінічні поля | Не видно версії перетворення | Сирий body у логах | Безмежні повтори | Чужі subject / event_type | K02 / K03 / K06; реальний адаптер не реалізований |
| Шлюз подій | Чужий HMAC / nonce | Зміна байтів / payload | «Не надсилав» | Помилка повертає body | Великий body / replay | Підпис вважають дозволом на будь-яку дію | K02–K04; HMAC не КЕП, R03 / R04 |
| API + домен | Прийнята клієнтська роль | Підміна case / команди | Дія без аудиту | Медичний ref командиру | DoS / блокування спільного IP | Доступ до чужого кейсу | K01 / K05 / K06; команди й повний домен 8а / 8б |
| Воркер / календар / outbox | Неправильна service identity | Відкат старою версією; орієнтир як строк | Немає журналу повторів | Дані в job payload | Нескінченний retry | Таймер сам зупиняє виплати | ADR 0003 / 0006, K03; стійка реалізація R05 / R06 |
| Реляційна БД | Спільний DBA / app account | Втрата атомарності | Редагований аудит | Backup / дамп / зайві поля | Відсутнє відновлення | Надмірні SQL-права | Логічні межі прийняті, фізичної БД немає; R05 / R11 |
| Документний broker | Викрадений токен джерела | Довільний URL / чужа версія | Читання без журналу | Прямий source URL / body | Довгий remote fetch | SSRF / обхід доступу джерела | K01, без remote fetch у демо; R07 |
| Запасне сховище | Фальшивий автор фото | Заміна «оригіналу» | Не відоме походження | Реальний файл у публічному repo | Шкідливий upload | Адмін читає всі зразки | Тільки підготовлена синтетика; uploads відсутні, R07 / R13 |
| Агрегатор | Неаналітична сесія | Зміна знаменника / фільтра | Невідомий snapshot | Малі / комплементарні / часові групи | Довільні дорогі зрізи | Drill-down до людини | K07; реальна OPSEC-політика R08 |

## LINDDUN: приватність

| Категорія | Наш сценарій / активи | Запобігання й залишок |
|---|---|---|
| Linking | Subject / incident / unit / provider refs дозволяють пов’язати різні дії | Розділені IdentityLink / AccessGrant, мінімальні DTO; реальні mapping / retention ще погодити |
| Identifying | Час лікування + мала частина ідентифікують людину без ПІБ | Немає реальних зрізів, географії / unit filters, fixed snapshot / suppression; k не доказ анонімності |
| Non-repudiation | Аудит надмірно фіксує всі медичні дії, від яких людина не може відмовитися | Лише необхідні адміністративні події, HMAC-теги й окремий доступ; строк / підстава реального аудиту [TBD] |
| Detecting | 403 / різні лічильники / час відповіді показують існування чужого кейсу | Однакова 404 для чужого / відсутнього case, без raw group sizes; повний timing-side-channel аудит не виконано |
| Data disclosure | Source ref / логи / резервна копія розкривають меддані | Явний DTO, 403 клініці командиру, без upload / remote fetch, аудит без body; захист backup ще R11 |
| Unawareness / Unintervenability | Людина не розуміє, хто бачить кейс, як виправити факт чи відкликати доступ | Видимі джерело / час / власник і адресне уточнення в 8б; родич не стає представником автоматично |
| Non-compliance | Дизайн підміняє підставу, згоду або авторизацію установи | Нормативний мапінг і блокування реальних даних; PR не сертифікат / рішення володільця |

## OPSEC: що показуємо в демо

Тільки фіксований **вигаданий** зріз без справжніх частин, закладів, місць і часових серій втрат. Навчальний поріг **5** — мінімальний параметр цього guard, а не норма чи гарантія анонімності. Якщо хоча б одна клітинка менша за поріг, приховуємо **всі клітинки й total**: жодного відновлення відніманням. Порожній / некоректний набір не перетворюється на нуль реальних втрат.

API не приймає довільних фільтрів, порога від клієнта, drill-down / списків людей, експорту рядків, unit / provider / geo вимірів. Немає живого оновлення чи порівняння довільних дат. Для реальних агрегатів потрібні рішення власника про достатню ширину когорти / гранулярність / затримку / частоту snapshot, контроль повторних і доповнювальних запитів, моніторинг зловживань та окремий OPSEC-допуск.

## Що є у пакеті фази 7

У [prototype/security](../../prototype/security/) — TypeScript strict, незалежне від вебфреймворку ядро та локальний HTTP-тестовий адаптер. Реалізовані серверна перевірка ролі / scope / відкликання й DTO, строгі JSON-схеми, HMAC і nonce / часовий інтервал, дедуплікація в межах запуску, ліміти / заголовки / generic errors, локальний приватний аудит і консервативне пригнічення синтетичного агрегату. Докази — негативні HTTP-тести, а не лише приховані кнопки.

Це **P0 безпеки**, не повний застосунок: немає чотирьох панелей, стійкої БД / inbox-outbox, SSO чи реального джерельного доступу. Тестовий вхід відповідає `validated_only`, `business_applied=false`, **не** «прийнято на виконання». Семантика приймання після стійкого запису з ADR 0003 не змінена; її інтеграція — 8а / 8б. Стек UI / фреймворк / СУБД / ORM / міграції ще не обрані.

Запуск перевірок — [README прототипу](../../prototype/README.md). Немає публічного сервера або deployment. Ключі тестів випадкові на кожен запуск; конфігураційний helper приймає секрети лише з env і відхиляє слабкі / повторені ключі / production. Порожній `.env.example` не містить секретів.

## Рішення команди

Рекомендований **варіант А**: затвердити реалізовані контролі ядра для синтетичного демо та обов’язкові незакриті інтеграційні перевірки 8а / 8б з реєстру. Деталізацію аналітики за частиною / закладом / місцем, реальні дані й довільні завантаження файлів лишити вимкненими. Не приймати production-ризики від імені установ.

Варіант **Б**: змінити конкретний демо-контроль / параметр до 8а. Числа нижче — запропоновані інженерні параметри демо, не нормативи чи доведена анонімність. До затвердження ризик не позначається «прийнятий командою».

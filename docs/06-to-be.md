## Межі моделі

Це **запропонований невиконуваний наскрізний процес**, а не опис запущеної системи чи універсальна процедура для кожного поранення. Один pool об’єднує навчальний сценарій координації; доріжки групують роботу, **не створюють єдиного органу влади чи підпорядкування лікарень, ВЛК та органу призначення ОГД**. У деталях кожна людська дія названа за належним виконавцем. Sequence flow — порядок у цій концептуальній моделі, а не API / передача медичних даних між організаціями. Міжорганізаційні договори й конкретні message flow реальних інтеграцій ще не встановлені.

Згорнутий підпроцес — окрема DI-площина. `receiveTask` означає очікування належного підтвердження, а не припущення про webhook. `serviceTask` — пропозиція автоматизації; реалізації ще немає. Вхід за повідомленням у деталізації ініціації — перший із двох дозволених сигналів; подієвий шлюз скасовує альтернативне очікування. Повторні / пізні сигнали йдуть у той самий кейс через перевірений шлюз, не запускають комплект задач знову. Неавторизований запит відхиляється до успішного маршруту.

Після завершення показаного проходу наступне звернення / подія потребує нового проходу координації за тим самим контролем; подієвий підпроцес працює лише поки активний батьківський процес. Це не модель безстрокового фонового воркера.

Клінічна гілка не чекає входу в Армія+, інтернету чи еПМК в сервісі. Адміністративний кейс може існувати без підтвердженого медичного факту. Медичні системи залишаються місцем вводу; нової форми клінічного запису в нашому продукті немає. Для відсутньої події / непогодженого адаптера залишається чинний дозволений документний маршрут і задача уточнення.

Кінець гілки означає завершення **цього проходу / обраного обсягу**, а не автоматичне закриття `WoundCase`, всіх періодів виплат чи задач. Стан «невідомо» у фінансових гілках очікує джерела; часткове виконання повертає в очікування решти. Обґрунтована відмова завершує цей розгляд, але не скасовує право на оскарження. ОГД у вибраному демонстраційному сценарії показана після ВЛК; це не твердження, що будь-яке право на ОГД завжди виникає лише після цієї конкретної ВЛК.

## Трасування до всього прийнятого обсягу

| F / AC | BPMN / умова поза вузлами |
|---|---|
| F01 / AC01 | `Sub_Intake`, `Gateway_NewCase`, `Control_Repeat`: підтвердження випадку, ручний розбір, повтор без дублювання |
| F02 / AC02 | `Control_Project`, `Control_Review`: джерело / час / свіжість / наступна задача; невідома подія лишається невідомою |
| F03 / AC03 | `Cert_*`, `VLK_Checklist`, `OGD_Checklist`, `Reward_Checklist`: окремі маршрути / правила, refs / отримання / виправлена версія |
| F04 / AC04 | `Cert_Anchor`, обидва `Timer_*`, `Care_Transfer`: відомі календарні якорі, ручний контроль, відсутність санкцій |
| F05 / AC05 | `VLK_Referral` → `VLK_Receipt` → `VLK_Decision` → `Task_ServiceExecution`: різні факти й належні виконавці |
| F06 / AC06 | `Sub_Reward` / `Sub_OGD`: різні правові підстави, періоди / пакети, причина / повернення / відмова / виконання |
| F07 / AC07 | `Control_Support`, адміністративна ініціація, чинний резерв; загальний гайд без доступу сторонньому; уточнення обліку без створення / скасування СЗЧ |
| F08 / AC08 | `Control_Aggregate`: визначення BO / когорт у фазі 5 й моделі даних; малі та доповнювальні групи приховуються; пороги уточнює фаза 7 |
| F09 / AC09 | Налагоджувальна панель не є посадовим учасником. У майбутньому подає лише синтетичні S1–S8 через той самий шлюз у `Sub_Intake` / `EventSub_Control`, з повторами, прогалинами й конфліктами |
| F10 / AC10 | Кожна дія / читання: серверна роль + чинний scope + дозволені поля; джерельний доступ перевіряється повторно. Чотири панелі, заборона клінічних даних командиру, неперсональні агрегати, аудит без PHI, чесний стан мережі й навчальний банер — наскрізні умови, не нові медичні кроки |

Наявність вузла не доводить виконання AC кодом. [P0–P4 / D1 і лінія відсікання](architecture/demo-plan.md) залишаються прийнятими: спершу основа й усі чотири панелі для 8а, потім наскрізний шлях та винятки, потім подача. При нестачі часу скорочуємо косметику / графіки / форми; F / AC й захист не вилучаємо мовчки. Для реалізації ця модель задає порядок, а не замінює фазу 7 або затвердження 8а.

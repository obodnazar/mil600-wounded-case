## Що перевірено

- C4 context / container та обидві ERD синтаксично перевірено **Mermaid 12.3.0** у Node.js 26.8.2 з DOM-оточенням: чотири блоки читаються без помилок. Це перевірка парсера, не заявлена візуальна експертиза чи робота запущеного сервісу. Тимчасові QA-залежності поза репозиторієм; стек прототипу не обирали.
- Перевірено локальні файли / якорі, таблиці, повноту F01–F10 / AC01–AC10 у архітектурному покритті, наявність усіх ERD-сутностей у словнику й внутрішніх JSON-прикладів. `python3 research/scripts/check-voices.py` та `git diff --check` проходять; дослідницькі реєстри й BPMN XML / SVG не змінені.
- У [реєстрі A01–A10](../architecture/sources.md) факти про системи відділені від нашого дизайну. A07–A09 повторно прочитано у живому браузері: reader повертав старі кешовані дати, для A08 2025-02-28 замість показаної сторінкою 2026-09-25. Це виправлено до фіксації джерела. Авторизованих запитів до медичних API не робили; Public / PROD у документації не оголошено дозволом новому сервісу.
- Семантику FHIR R4 звірено з HL7; Patient / Encounter / EpisodeOfCare / DocumentReference не видано за однаково доступні endpoints українського ЕСОЗ. Метод Composition іншого призначення не названо універсальним епікризом; документація інших країн не використана. Старі технічні матеріали позначено, статистику з них не переносили в пітч.
- Зіставлено принцип «лікарям без нового застосунку», окремі №001/о / №002/о, паперовий резерв, СЕДО / ЕСОЗ як різні маршрути, непідтверджені права й API. Реальні джерела на C4 — цільові погоджувані залежності, у прототипі будуть моки.
- Перевірено логіку: відкрити адміністративний кейс без медичного факту; та сама особа / інше поранення; невизначений збіг; повтор після збою; той самий ID з іншим digest; пізня / непрозоро версійована подія; прогалина джерела; відкликання / нова версія документа й квитанція конкретному адресату; атомарні зміни / аудит / outbox. Exactly-once між установами не обіцяється.
- Anchor п’ятиденного правила явно є отриманням визначеного документа **військовослужбовцем** за застосовності N16 ст.260, а не часом inbox / створенням еПМК / одержанням ВЛК. Невідомий anchor дає null і уточнення; переведення не обнуляє лікування. Injury_date не виводиться з дати відкриття кейсу; спеціальне правило ОГД з N07 лишається врахованим.
- Межі доступу охоплюють роль + scope + чинність + поле, документи / їхні refs, кеш і відкликання. Командир / супровід не стають медиками; dev / integration identity не видає собі AccessGrant. Аналітик не отримує рядків людей; мінімальна група сама не названа анонімністю, потрібне комплементарне пригнічення й OPSEC-оцінка фази 7.
- Всі BO мають джерела в моделі / ознаку невідомого; BO-5 включає неотримані потрібні документи в знаменник, BO-6 не підміняє робочий час віком кейсу. Контекстний BO-4 не став виміряним ефектом. Baseline [TBD], запити не надсилалися.
- D1 / P0–P4 і лінія відсікання зберігають чотири панелі й прийняті F / AC. Першими спрощуються подача / фільтри / форми, не серверні перевірки чи правдивість статусу. Якщо AC не готовий, MVP не називається завершеним; потрібне явне нове рішення. Вимогу простої сторінки пітчу записано для фази 9, сама фаза 9 не виконувалася.

## Межі та наступне рішення

Немає реальних API / SSO-контрактів, регламенту mapping / посадових полів, внутрішніх схем, домовленостей установ, production-захисного допуску, емпіричних baseline чи тестів на живих користувачах. Право джерела / оригінальність документа не доводиться HMAC нашого конверта. Число мінімальної групи — запропонована демо-конфігурація; реальні пороги / OPSEC та технічні контролі затверджуються у фазі 7. Жоден захисний механізм не названо вже реалізованим.

Рекомендовано погодити логічні межі сервісу / моделі / доступів і ADR 0002–0005 із цими обмеженнями. Включення до реальної ІКС «Супровід» потребує відповіді власника. Стек і фізичні міграції — фаза 8а; наступна фаза після нового затвердження — 7. Після PR фази 6 — зупинка, без автоматичного злиття.

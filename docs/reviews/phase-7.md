## Докази й відтворення

- Локально Node.js **26.8.2**: `npm ci --ignore-scripts`, `npm run lint`, `npm test`, `npm run build`, `npm audit --audit-level=high`. **22 тести пройдено**, failure / skip / todo **0**; аудит залежностей **0** вразливостей після override. Команди — [README](../../prototype/README.md), точні версії — package-lock. Це фактичний тест ядра, а не скриншот прихованої кнопки.
- Тести відкривають HTTP лише на loopback / випадковому порту: 403 командиру / супроводу на клініку, explicit DTO без зайвих полів, foreign / missing case, role injection, revoked / expired scope, без сесії / cross-origin / unsafe method, safe headers, schema / tamper / source scope / recipient / signature / stale / future / concurrent replay / boundary, duplicate / conflict / новий ID тієї самої ревізії, payload size / rate / spoofed X-Forwarded-For, приватний аудит / sentinel / audit failure, fixed aggregate / suppression / відсутність фільтрів, env / слабкі й повторені ключі / production guard.
- JSON Schema — 17 визначених типів власного конверта, додаткові поля заборонені, дати перевіряє AJV formats. HMAC перевіряється до parse; права й тип джерела — окремо. Немає довільних URL / реальних upload / grants у події; HMAC не КЕП / медична істина. Виплата / службовий статус / юридичний строк модулем не змінюються.
- `asvs-coverage.json` звірений з офіційним CSV v5.0.0: **253** ID рівнів 1–2; **17 module_tested**, **9 partial**, **2 planned**, **225 not_assessed**. Сума збігається; module_tested не є сертифікацією застосунку. Мапінг не приховує TLS / SSO / storage / operations прогалини.
- STRIDE охоплює 13 компонентів / груп контейнерів C4 і 9 потоків; LINDDUN — сім категорій; OPSEC — групи / віднімання / час / географія / need-to-know. Реєстр має 22 ризики, включно з adoption, лікарнями поза каналом, правом, шахрайством, помилковим identity, двома виплатами та дедлайном. Це авторські оцінки ризику, не виміряні частоти атак.
- CI містить quality / CodeQL / gitleaks, actions pinned до звірених commit SHA; gitleaks v3 сумісний із Node24 runtime actions. Автоматичні PR-comments / повідомлення й secret artifacts вимкнені. Статус віддаленого запуску перевіряється для head PR перед фінальним звітом; сам YAML не названо зеленим CI. Локальний gitleaks 8.30.1 отримано з офіційного release із перевіркою SHA256; скан історії — перед PR.
- Локальні посилання / таблиці / JSON, зв’язки R / K / ASVS, публічний склад diff і `git diff --check` перевірені. Скриншот чату, реальні документи / персональні дані / ключі / node_modules / dist / runtime audit не включені. Окремий текст відповіді команді надається користувачу в чаті, нікому не надсилався.

## Правки TO BE й джерела

За прямою інструкцією користувача спершу внесено дві правки в PR #7: основна еПМК з МІС ЗСУ / адміністративний резерв, повна назва **«довідка про обставини травми (додаток 5 до Наказу №402)»**, начальник медслужби складає / командир видає, правило ст.260 лише за дій противника й отримання документа військовослужбовцем. Дата внесення — лише орієнтир «дату отримання підтвердити», юридичний due_date null до підтвердження, жодних санкцій. Це [ADR 0006](../architecture/adr/0006-primary-trigger-and-certificate-clock.md). Після повторних XSD / SVG / структурних перевірок і окремого дозволу користувача PR #7 злитий; фаза 7 має його базою, не дублює той PR.

Нормативний мапінг спирається на прийняті конспекти N01–N21 із датами / редакціями; ст.260 повторно прочитана у повному тексті ВРУ через окремий HTTP-запит після timeout reader. OWASP ASVS 5.0.0 / CSV, Microsoft STRIDE, LINDDUN, Node crypto, GitHub CodeQL / gitleaks й advisory minimatch відкриті як першоджерела; дати й посилання — у відповідних security-документах. Нових цитат, оцінок поширеності / ефекту або прав установ не вигадано.

## Межі й рішення

Це переносиме ядро **P0** за [ADR 0007](../architecture/adr/0007-security-foundation.md), не вибір UI-фреймворку / СУБД / ORM / hosting і не виконана 8а. HTTP-вхід чесно повертає `validated_only`, `business_applied=false`; ledger у пам’яті не переживає restart. До доменних ефектів потрібні durable inbox / outbox / транзакція, аудит / source reauthorization, UI / session / CSRF / TLS, повторні end-to-end перевірки й чотири панелі. Повні метрики, календар / підтвердження строку й D1 реалізуються в 8б. Немає реальних API, публічного запуску, захисного допуску, baseline / інтерв’ю / пентесту чи production-приймання.

Рекомендовано **А**: затвердити реалізовані контролі модуля / демо-параметри та обов’язкові залишкові перевірки 8а / 8б; реальні дані й unit / provider / geo аналітика заблоковані. Варіант **Б** — конкретно змінити контроль / параметр перед 8а. ASVS / правові / OPSEC-ризики production команда не приймає від імені установ. P0–P4 / мінімальний D1 / лінія відсікання збережені; безпека не скорочується заради 03.12.

Після PR фази 7 — **зупинка, без автоматичного merge**. Наступна точка лише після «Затверджую фазу 7»: **8а — стек / фізична схема / перший екран кожної панелі** → окреме затвердження, потім 8б → решта 9.

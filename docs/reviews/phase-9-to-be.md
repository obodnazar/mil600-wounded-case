## Технічні докази

- BPMN20 XSD через `xmllint`: валідно. `bpmn-moddle 10.3.1`: parse / round-trip без попереджень; **8 DI-площин, 5 доріжок огляду, 118 flow nodes, 121 sequence flow, 142 DI shapes, 121 DI edges**. Це характеристики файлу, не емпіричні показники процесу.
- `bpmn-js Modeler 18.31.1`, Node.js 26.8.2, Playwright 1.62.1, локальний headless Chrome: імпорт, `saveXML()`, повторний імпорт, відкриття кожної площини й `saveSVG()` без попереджень. Жодного звернення до реального медичного API або завантаження в публічний редактор. QA-залежності / PNG поза репозиторієм.
- Перевірено правильність посилань / incoming / outgoing, належність до доріжки, DI для кожного вузла / потоку, ортогональні стрілки без перетину сторонніх вузлів, межі підпроцесів, досяжність і можливий шлях до кінця, умови / default-гілки, non-interrupting таймери. Генератор відтворює XML; експорт читає канонічний XML, не редагує його.
- Переглянуто огляд та всі сім деталей: ролі, підписи, паралельність, цикли уточнення й повернення. Експортер перевіряє фактичні межі зовнішнього тексту після розкладки bpmn-js: **0 накладань** на сторонні вузли / інші зовнішні підписи на кожній площині. Це допоміжна перевірка, не заміна огляду чи повний аналіз усіх перетинів ліній.
- Точні ID у порівняльній таблиці / описі існують у збереженому AS IS або TO BE; F01 / AC01 … F10 / AC10 присутні в окремому трасуванні. Локальні посилання, таблиці та `git diff --check` перевірені. AS IS XML / SVG, матеріали дослідження й затверджені вимоги F / AC не змінювалися.

## Сценарії та межі

Пройдено сценарії [опису](../06-to-be.md): еПМК / адміністративний запит першими; повтор / конфлікт digest; інше поранення тієї самої особи; невизначений збіг; переведення / відсутня подія; відомий / невідомий якір; неповний чекліст без заборони направлення; явне повернення до автора; нова версія й окреме отримання; постанова ВЛК та службове виконання; паралельна винагорода; застосовність / незастосовність / невідомі підстави ОГД; повернення / відмова / невідомий стан / призначення / часткове виконання; супровід без входу бійця; заборона клініки командиру / захист груп як наскрізні вимоги.

Перевірено відповідність прийнятим ADR: адміністративний кейс не створює медичного факту; відсутня подія не є доказом порушення; таймер не змінює СЗЧ / право / виплату; 4 календарні місяці від початку лікування, застосовний п’ятиденний строк — від отримання визначеного документа військовим. Довідку складає начмед і видає командир, направляє належний суб’єкт, оглядає / постановляє ВЛК. ОГД й винагорода різні; строк рішення не є строком банківського зарахування. Копія / ref / оригінал / отримання різняться. Права, ідентичність, джерельні версії й збереження мінімальних метаданих відповідають логічній архітектурі.

Норми зіставлено з прийнятими конспектами [N01–N21](../../regulation/README.md) та [матрицею](../../regulation/legality-matrix.md) зі зрізом 2026-11-13. Нових правових висновків, цитат або чисел поширеності не додавали. Технічні першоджерела OMG / bpmn-js відкрито; публікація / дата перевірки в [описі](../06-to-be.md). Внутрішні посилання ведуть до наявних артефактів; старі рев’ю залишаються історією.

Один pool — навчальна координація, не реальний міжорганізаційний виконуваний контракт. Умови / дати описові; XSD й досяжність не є повним token-симулятором. Подієвий підпроцес активний лише поки активний батьківський процес; наступний прохід не означає нове поранення чи автоматичне закриття / відкриття WoundCase. Паперовий резерв та оригінали не скасовано. API, власники / регламенти обміну, production-захист, baseline та ефект на час залишаються [TBD]; запити baseline не надсилалися.

`npm test / lint / build` прототипу не застосовуються: застосунку ще немає й код `prototype/` не додавався. У фазі 7 потрібні ризики й конкретні демо-контролі; стек / міграція / перші екрани чотирьох панелей — лише в 8а, з окремим затвердженням. Решта 9 / фінальне рев’ю / питання комітету / проста сторінка пітчу не виконувалися. Мінімальний D1 / P0–P4 і лінія відсікання збережені.

**Рішення:** рекомендовано варіант А — прийняти TO BE для кроку II з переліченими межами. Альтернатива Б — конкретні правки до маршруту. Після PR — зупинка; наступна фаза 7 лише після затвердження цього пакета. Автоматичного злиття PR немає.
